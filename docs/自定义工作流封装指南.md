# Canvas 自定义工作流封装指南

本文说明如何把一个已经能够在 ComfyUI 中正常运行的工作流，封装成 Canvas Gateway 可以调用的工作流模板。

本文同时面向两类读者：

- 第一次接触工作流封装的普通用户；
- 需要根据 ComfyUI 工作流自动编写 JSON 配置的 AI 编程助手。

本文只说明当前版本已经支持的手工封装方式。APP 内“导入工作流”功能尚未实现，因此添加工作流时仍需在电脑上放置文件并编辑配置。

项目同时提供机器可读的 [workflow-profile.schema.json](workflow-profile.schema.json)，可用于检查单个 Canvas 工作流定义的基本结构。该 Schema 只能检查字段类型和取值范围，不能代替节点编号、输入名和实际执行测试。

---

## 一、最终需要准备的两个部分

一个可被 Canvas 调用的工作流由两个部分组成。

### 1. API 格式工作流模板

这是 ComfyUI 实际执行的节点图，文件扩展名为 `.json`。它必须使用 ComfyUI 的 **API Format** 导出。

推荐存放位置：

```text
%APPDATA%\CanvasGateway\workflows\
```

例如：

```text
%APPDATA%\CanvasGateway\workflows\my_anima_hires.json
```

### 2. Canvas 工作流定义

这是写入 `%APPDATA%\CanvasGateway\config.json` 的一段配置。它用于告诉 Gateway：

- 工作流的名称和文件位置；
- 工作流使用 checkpoint 还是独立 UNet；
- APP 应显示普通生图参数还是高清修复参数；
- 正向提示词、负向提示词、尺寸、采样步数等参数分别对应哪个节点输入。

工作流定义不是 ComfyUI 节点图。它只是 Canvas 与节点图之间的“参数地址表”。

---

## 二、先理解三个容易混淆的概念

### 1. ComfyUI 界面格式

界面格式用于保存画布布局、分组、节点位置、折叠状态等内容。常见特征是 JSON 顶层包含：

```json
{
  "nodes": [],
  "links": []
}
```

Canvas Gateway **不能直接提交这种格式**。

### 2. ComfyUI API 格式

API 格式只保留执行工作流所需的节点、输入和连接。常见结构如下：

```json
{
  "7": {
    "inputs": {
      "text": "a sample prompt",
      "clip": ["3", 0]
    },
    "class_type": "CLIPTextEncode",
    "_meta": {
      "title": "Positive Prompt"
    }
  }
}
```

顶层键 `"7"` 是节点编号。`inputs.text` 是该节点的一个输入。`class_type` 是 ComfyUI 后端识别的节点类型。

### 3. `node_map`

`node_map` 把 Canvas 参数映射到 API 工作流中的具体输入。例如：

```json
"positive": {"node": "7", "input": "text"}
```

含义是：用户在 APP 中提交的正向提示词，需要写入节点 `7` 的 `inputs.text`。

如果节点编号或输入名写错，可能出现以下结果：

- ComfyUI 拒绝工作流；
- APP 中修改了参数，但实际生图仍使用模板中的旧值；
- Gateway 提示工作流缺少某个节点；
- 图片生成成功，但使用了错误的参数或模型。

## 三、准备工作

开始前应完成以下检查：

1. 在 ComfyUI 网页中打开目标工作流；
2. 安装工作流所需的全部自定义节点；
3. 放置工作流所需的底模、文本编码器、VAE、LoRA、ControlNet 和放大模型；
4. 在 ComfyUI 网页中至少完整运行一次；
5. 确认最终输出连接到了 `SaveImage` 或其他能在 ComfyUI 历史记录中返回图片的输出节点；
6. 备份 `%APPDATA%\CanvasGateway\config.json`。

不要从一个在 ComfyUI 中本身就报错的工作流开始封装。Canvas 只负责替换参数并提交节点图，不会修复缺失节点、缺失模型或错误连接。

---

## 四、从 ComfyUI 导出 API 格式工作流

不同 ComfyUI 前端版本的菜单名称可能略有差异，但处理原则相同。

1. 打开 ComfyUI 设置；
2. 启用开发者模式或开发者选项；
3. 找到“保存 API 格式”“Export API”或“Save (API Format)”；
4. 将文件保存为容易辨认的英文文件名，例如 `my_anima_hires.json`；
5. 使用文本编辑器打开该文件；
6. 确认顶层没有 `nodes` 数组；
7. 确认顶层是由节点编号组成的对象，例如 `"2"`、`"7"`、`"10"`。

如果文件顶层包含 `nodes` 和 `links`，说明导出的仍是界面格式，应返回 ComfyUI 重新导出。

---

## 五、把模板放到不会被升级覆盖的位置

将 API 格式工作流复制到：

```text
%APPDATA%\CanvasGateway\workflows\
```

如果 `workflows` 文件夹不存在，可以手工新建。

推荐使用该位置的原因如下：

- 安装新版 Gateway 时不会覆盖；
- 卸载 Gateway 时默认不会删除；
- 便携版和安装版均能优先读取；
- 不需要寻找安装目录；
- 不会把私人工作流误提交到公开 Git 仓库。

不建议把私人工作流放进程序安装目录，也不建议放进仓库的 `gateway/workflows`。后者适合项目维护者随软件分发公共模板，不适合保存个人工作流。

## 六、识别需要暴露给 APP 的节点输入

打开 API 格式 JSON，根据 `class_type` 和 `_meta.title` 查找对应节点。

通常需要识别以下内容：

| Canvas 参数 | 常见节点 | 常见输入名 | 用途 |
|---|---|---|---|
| `positive` | `CLIPTextEncode` 或提示词节点 | `text`、`positive` | 正向提示词 |
| `negative` | `CLIPTextEncode` 或提示词节点 | `text`、`negative` | 负向提示词 |
| `width` | `EmptyLatentImage`、尺寸节点 | `width` | 输出宽度 |
| `height` | `EmptyLatentImage`、尺寸节点 | `height` | 输出高度 |
| `steps` | `KSampler` 或自定义采样器 | `steps` | 一采步数 |
| `cfg` | `KSampler` 或自定义采样器 | `cfg` | 一采 CFG |
| `seed` | `KSampler` 或噪声节点 | `seed`、`noise_seed` | 一采种子 |
| `sampler_name` | `KSampler` 或自定义采样器 | `sampler_name` | 一采采样器 |
| `scheduler` | `KSampler` 或自定义采样器 | `scheduler` | 一采调度器 |
| `hires_steps` | 二采节点 | `steps` | 二采步数 |
| `hires_cfg` | 二采节点 | `cfg` | 二采 CFG |
| `hires_denoise` | 二采节点 | `denoise` | 二采重绘强度 |
| `hires_sampler_name` | 二采节点 | `sampler_name` | 二采采样器 |
| `hires_scheduler` | 二采节点 | `scheduler` | 二采调度器 |
| `kernel_size` | 部分分块放大节点 | `kernel_size` | 高清修复核大小 |
| `filename_prefix` | `SaveImage` | `filename_prefix` | 临时输出目录前缀 |
| `base_model` | `CheckpointLoaderSimple`、`UNETLoader` | `ckpt_name`、`unet_name` | APP 选择的底模 |
| `lora_stack` | 当前兼容的 LoRA 堆节点 | `lora_str` | APP 选择的 LoRA 列表 |

节点标题只能辅助判断。最终必须以 API JSON 中实际存在的节点编号和输入名为准。

### 识别示例

假设 API JSON 中存在：

```json
"10": {
  "inputs": {
    "seed": 123456789,
    "steps": 30,
    "cfg": 4.5,
    "sampler_name": "er_sde",
    "scheduler": "simple",
    "denoise": 1.0
  },
  "class_type": "KSampler"
}
```

对应映射应写为：

```json
"steps": {"node": "10", "input": "steps"},
"cfg": {"node": "10", "input": "cfg"},
"seed": {"node": "10", "input": "seed"},
"sampler_name": {"node": "10", "input": "sampler_name"},
"scheduler": {"node": "10", "input": "scheduler"}
```

## 七、编写工作流定义

以下是一个完整的普通文生图定义示例：

```json
{
  "id": "my_anima_txt2img",
  "label": "My Anima TXT2IMG",
  "path": "workflows/my_anima_txt2img.json",
  "model_kind": "unet",
  "model_dirs": [],
  "features": ["txt2img"],
  "defaults": {
    "width": 896,
    "height": 1152,
    "steps": 30,
    "cfg": 4.5,
    "seed": -1
  },
  "node_map": {
    "positive": {"node": "7", "input": "text"},
    "negative": {"node": "8", "input": "text"},
    "width": {"node": "9", "input": "width"},
    "height": {"node": "9", "input": "height"},
    "steps": {"node": "10", "input": "steps"},
    "cfg": {"node": "10", "input": "cfg"},
    "seed": {"node": "10", "input": "seed"},
    "sampler_name": {"node": "10", "input": "sampler_name"},
    "scheduler": {"node": "10", "input": "scheduler"},
    "filename_prefix": {"node": "12", "input": "filename_prefix"},
    "lora_stack": {"node": "5", "input": "lora_str"},
    "base_model": {"node": "2", "input": "unet_name"}
  }
}
```

### 字段说明

#### `id`

工作流的稳定标识。建议只使用小写英文字母、数字和下划线，例如：

```text
my_anima_txt2img
```

一旦用户已经开始使用，尽量不要修改。APP 会按该值保存每个工作流的底模和负面提示词设置。

#### `label`

APP 中显示的名称。可以使用中文或英文。

#### `path`

相对于 `%APPDATA%\CanvasGateway` 的路径。若模板位于：

```text
%APPDATA%\CanvasGateway\workflows\my_anima_txt2img.json
```

则填写：

```json
"path": "workflows/my_anima_txt2img.json"
```

不要把用户电脑的绝对路径写进准备公开分享的定义。

#### `model_kind`

常用值：

- `"checkpoint"`：底模由 checkpoint 加载节点读取；
- `"unet"`：底模由独立 UNet 或 diffusion model 加载节点读取。

它主要用于模型列表的分类和展示。真正替换哪个输入仍由 `node_map.base_model` 决定。

#### `model_dirs`

可选的模型扫描目录列表。空数组表示使用 Gateway 全局配置的 `checkpoint_dirs`。

个人配置可以填写绝对路径，例如：

```json
"model_dirs": [
  "D:/AI/ComfyUI/models/diffusion_models",
  "D:/AI/ComfyUI/models/checkpoints"
]
```

准备公开分享时应保持空数组，让用户的安装向导和本机配置决定目录。

#### `model_include_patterns`

可选的文件名筛选规则。仅显示文件名中包含任一规则的模型，不区分大小写。

例如：

```json
"model_include_patterns": ["anima"]
```

不要把筛选条件写得过窄，否则兼容底模可能不会出现在 APP 中。

#### `features`

当前常用值：

- `"txt2img"`：普通文生图工作流；
- `"hires"`：APP 显示二采高清修复参数。

例如：

```json
"features": ["txt2img", "hires"]
```

`features` 只控制 APP 能力和界面，不会自动创建任何 ComfyUI 节点。工作流模板本身必须已经包含相应流程。

#### `defaults`

用户第一次选择该工作流时使用的默认值。当前请求参数限制如下：

| 字段 | 范围或要求 |
|---|---|
| `width`、`height` | 512～2048，且必须是 64 的倍数 |
| `steps`、`hires_steps` | 1～100 |
| `cfg`、`hires_cfg` | 0～30 |
| `hires_denoise` | 0～1 |
| `hires_kernel_size` | 1～8 |
| `seed` | `-1` 表示随机，或 0～9223372036854775807 |

#### `node_map`

每一项都由两个字段组成：

```json
{"node": "节点编号", "input": "输入名"}
```

节点编号统一写成字符串。输入名必须与 API JSON 中 `inputs` 对象的键完全一致，包括大小写。

    "cfg": {"node": "103", "input": "cfg"},
    "seed": {"node": "103", "input": "seed"},
    "sampler_name": {"node": "103", "input": "sampler_name"},
    "scheduler": {"node": "103", "input": "scheduler"},
    "hires_seed": {"node": "42", "input": "seed"},
    "hires_steps": {"node": "42", "input": "steps"},
    "hires_cfg": {"node": "42", "input": "cfg"},

    "hires_sampler_name": {"node": "42", "input": "sampler_name"},

## 九、LoRA 堆的特殊要求

当前 Canvas 的动态 LoRA 功能不是对任意数量的标准 `LoraLoader` 节点逐个修改，而是把 APP 选择结果编码成 JSON 字符串，再写入一个兼容的 LoRA 堆输入。

Gateway 写入的内容形如：

```json
[
  {
    "lora": "example.safetensors",
    "weight": 0.8,
    "text_encoder_weight": 0.8
  }
]
```

但在 API 工作流节点中，该值实际保存为字符串，例如：

```json
"lora_str": "[{\"lora\":\"example.safetensors\",\"weight\":0.8,\"text_encoder_weight\":0.8}]"
```

当前内置 Anima Base 模板使用的节点类型是：

```text
WeiLinPromptUIOnlyLoraStack
```

界面名称通常显示为：

```text
WeiLin LoRA 堆
```

该节点来自第三方项目 [WeiLin-Comfyui-Tools](https://github.com/weilin9999/WeiLin-Comfyui-Tools)，不是 ComfyUI 内置节点，也不是 Canvas 自有代码。其上游采用 GPL-2.0 许可证。

对应映射为：

```json
"lora_stack": {"node": "5", "input": "lora_str"}
```

如果目标工作流没有兼容的字符串型 LoRA 堆输入，应采取以下一种方式：

1. 在模板中固定 LoRA，不向 APP 暴露动态 LoRA；
2. 安装并使用兼容的 LoRA 堆节点；
3. 修改 Gateway，使其支持目标 LoRA 节点的输入协议；
4. 等待后续工作流导入与节点适配功能。

不要把 `lora_stack` 映射到普通 `LoraLoader` 的 `lora_name`。两者的数据格式完全不同。

## 十、第三方节点和模型依赖

API 工作流中的每一个 `class_type` 都必须能被目标 ComfyUI 识别。

### 1. 如何判断节点是否为第三方节点

可以使用以下方法：

1. 在 ComfyUI Manager 的“缺失节点”功能中检查；
2. 在 ComfyUI 节点菜单中查看节点所属扩展；
3. 在 `ComfyUI/custom_nodes` 中搜索 `NODE_CLASS_MAPPINGS`；
4. 把 API JSON 中的 `class_type` 与 ComfyUI 核心节点列表对照；
5. 暂时移走可疑扩展后启动 ComfyUI，观察是否报告缺失节点。该方法只适合了解 ComfyUI 目录结构的用户。

### 2. 分享工作流时必须列出依赖

至少记录：

- 节点项目名称；
- 官方仓库地址；
- 建议版本、标签或提交哈希；
- 许可证；
- Python 依赖；
- 模型名称和放置目录；
- 是否会访问网络；
- 是否需要重启 ComfyUI。

### 3. 安全要求

工作流 JSON 只是配置，但自定义节点通常包含可执行 Python 和前端 JavaScript。安装第三方节点等同于允许其在 ComfyUI 进程中执行代码。

只应从可信上游安装节点。不要让 AI 从不明网盘、匿名压缩包或无法核实来源的镜像自动安装自定义节点。

## 十一、在 `config.json` 中注册工作流

关闭 Canvas Gateway，然后打开：

```text
%APPDATA%\CanvasGateway\config.json
```

找到顶层的 `workflows` 数组，把新工作流定义作为一个对象加入数组。

以下是配置结构片段示例。应在现有 `config.json` 中编辑对应字段，不要直接用示例覆盖自己的完整配置：

```json
{
  "comfy_url": "http://127.0.0.1:8188",
  "comfy_python": "D:/AI/python/python.exe",
  "comfy_workdir": "D:/AI/ComfyUI",
  "comfy_output_dir": "D:/AI/ComfyUI/output",
  "default_workflow": "my_anima_txt2img",
  "workflows": [
    {
      "id": "my_anima_txt2img",
      "label": "My Anima TXT2IMG",
      "path": "workflows/my_anima_txt2img.json",
      "model_kind": "unet",
      "model_dirs": [],
      "features": ["txt2img"],
      "defaults": {
        "width": 896,
        "height": 1152,
        "steps": 30,
        "cfg": 4.5,
        "seed": -1
      },
      "node_map": {
        "positive": {"node": "7", "input": "text"},
        "negative": {"node": "8", "input": "text"},
        "width": {"node": "9", "input": "width"},
        "height": {"node": "9", "input": "height"},
        "steps": {"node": "10", "input": "steps"},
        "cfg": {"node": "10", "input": "cfg"},
        "seed": {"node": "10", "input": "seed"},
        "filename_prefix": {"node": "12", "input": "filename_prefix"},
        "base_model": {"node": "2", "input": "unet_name"}
      }
    }
  ]
}
```

### 重要：`workflows` 会整体替换内置列表

当前版本中，只要用户配置包含非空 `workflows` 数组，Gateway 就会使用该数组，而不会自动把内置工作流追加进去。

因此：

- 只写一个自定义定义时，APP 中将只显示这一个工作流；
- 若要保留 Anima Base 和 IL 2.6，应把它们的定义也保留在同一个数组中；
- 内置定义可以从 `gateway/canvas_gateway/config.py` 的 `DEFAULT_WORKFLOWS` 查看；
- 编辑前必须备份原配置。

未来实现工作流导入界面时，应由程序完成合并、重名检查和备份，避免用户手工维护整个数组。

## 十二、重启和验证

保存配置后执行以下步骤：

1. 确认 JSON 文件没有多余逗号、注释或中文引号；
2. 重启 Canvas Gateway；
3. 打开 APP 的工作流选择；
4. 确认新工作流名称已经出现；
5. 检查底模列表是否合理；
6. 使用较低步数执行一次测试；
7. 分别修改正向提示词、负向提示词、尺寸、种子和采样参数；
8. 检查生成结果是否确实反映了这些修改；
9. 若存在高清修复，再分别验证一采和二采参数；
10. 查看 `%APPDATA%\CanvasGateway\logs` 是否存在异常。

不能只以“成功生成了一张图”作为通过标准。还必须确认所有暴露参数都写入了正确的节点。

---

## 十三、哪些情况不需要更新 APP

通常不需要更新 APP 的情况：

- 新工作流只使用现有参数；
- 只更换节点编号；
- 只更换模型、VAE、固定 LoRA 或固定放大节点；
- 只新增模板内部的固定处理步骤；
- 只增加一个普通文生图或现有形式的高清修复工作流；
- 使用现有 `workflow_id`、底模、LoRA、尺寸、采样器、调度器和二采参数即可完成控制。

APP 会通过 Gateway 的工作流接口动态读取工作流列表，因此新增符合现有能力的工作流不必重新打包 APK。

---

## 十四、哪些情况需要修改 Gateway 或 APP

以下需求不能只靠工作流 JSON 和 `node_map` 完成：

- 上传图生图原图；
- 上传姿势参考图、ControlNet 图或遮罩；
- 在 APP 中选择启用或关闭工作流分支；
- 动态控制多个 ControlNet；
- 区域提示词、局部重绘、画布遮罩；
- 动态改变放大倍率、分块尺寸或当前未支持的自定义参数；
- 对多个标准 LoRA Loader 节点进行动态增删；
- 视频、音频或多文件输入；
- 工作流需要新的文件上传接口；
- APP 需要新的控件或新的参数类型。

这类功能至少需要完成以下工作：

1. 扩展 Gateway 的请求模型；
2. 扩展 `build_workflow()` 的参数写入逻辑；
3. 必要时增加安全的文件上传、校验和清理；
4. 扩展 APP 界面和本地状态保存；
5. 增加自动化测试；
6. 重新构建 Gateway，若 APP 界面或请求结构变化则重新构建 APK。

## 十五、常见错误及处理方法

### 错误 1：Gateway 提示“当前文件不是 API 格式工作流”

原因：导入了 ComfyUI 界面格式。

处理：启用开发者选项，重新导出 API Format。

### 错误 2：ComfyUI 提示缺少节点

原因：API JSON 中的 `class_type` 未注册。

处理：查明节点的官方来源，安装正确版本并重启 ComfyUI。不要随意替换成名称相似的节点。

### 错误 3：修改 APP 参数后没有效果

原因：`node_map` 指向错误节点，或映射到了未参与最终输出的支路。

处理：沿最终 `SaveImage` 节点反向检查连接，确认映射节点位于真正执行的支路中。

### 错误 4：工作流列表中原有项目消失

原因：用户的非空 `workflows` 数组替换了内置列表。

处理：把希望保留的所有工作流定义放回同一个数组。

### 错误 5：底模列表为空或缺少兼容模型

原因可能包括：

- `model_dirs` 或全局 `checkpoint_dirs` 路径错误；
- `model_include_patterns` 过于严格；
- `model_kind` 与模型目录不匹配；
- 模型扩展名不受支持；
- 模型位于未扫描的目录。

### 错误 6：LoRA 在 APP 中可选，但工作流拒绝执行

原因：目标节点不接受 Canvas 的 LoRA 堆 JSON 字符串，或 LoRA 文件名与扫描结果不一致。

处理：确认节点类型、`lora_str` 输入和 LoRA 相对文件名。

### 错误 7：生成结束但 APP 没有图片

原因可能包括：

- 最终节点没有返回 `images`；
- 映射到的 `filename_prefix` 不是最终保存节点；
- `comfy_output_dir` 与 ComfyUI 实际输出目录不同；
- 工作流只包含预览节点，输出类型与 Gateway 预期不一致；
- 最终图片由特殊节点保存，未写入 ComfyUI 历史记录。

优先使用标准 `SaveImage` 作为最终输出。

## 十六、交给 AI 编写配置时的输入材料

为了让 AI 准确编写工作流定义，应一次性提供以下材料：

1. 完整的 API 格式工作流 JSON；
2. 希望在 APP 中控制的参数列表；
3. 工作流是文生图、图生图还是高清修复；
4. 底模由 checkpoint 还是独立 UNet 加载；
5. 是否需要动态 LoRA 堆；
6. 工作流所需的自定义节点及其来源；
7. 希望显示的工作流名称和稳定 `id`；
8. 默认尺寸、步数、CFG、采样器、调度器和二采参数；
9. 是否允许修改 API 工作流本身；
10. 当前 Canvas Gateway 的版本或对应代码。

不要只提供 ComfyUI 截图。截图适合解释布局，但无法可靠确定 API 节点编号、输入名和连接数据。

---

## 十七、AI 生成配置的强制规则

负责封装的 AI 应遵守以下规则：

1. 只接受 API 格式工作流作为执行模板；
2. 不得根据截图猜测节点编号；
3. 不得发明 API JSON 中不存在的节点、输入名或模型文件；
4. `node_map` 中的每个 `node` 必须存在于模板顶层；
5. `node_map` 中的每个 `input` 必须存在于对应节点的 `inputs` 中；
6. 节点编号必须输出为字符串；
7. 不得改变原节点连接，除非用户明确授权修改工作流；
8. 不得把私人绝对路径、访问令牌、代理凭据、配对码或 API Key 写入公开模板；
9. 必须列出所有非核心 `class_type` 的来源和许可证；
10. 必须区分“已从文件验证”和“基于命名推断”；
11. 对无法确定的映射应标为未确认，不得用猜测值填充；
12. 输出前必须验证 JSON 语法；
13. 输出后必须生成一份逐项映射审计表；
14. 必须说明该工作流是否需要更新 APP 或 Gateway；
15. 如果配置非空 `workflows` 数组，必须提醒它会替换内置列表。

<粘贴 JSON>

## 十九、AI 输出后的人工复核清单

即使配置由 AI 生成，也应逐项完成以下检查：

- [ ] 模板是 API 格式，不包含顶层 `nodes` 数组；
- [ ] 每个 `node_map.node` 都能在模板顶层找到；
- [ ] 每个 `node_map.input` 都能在对应 `inputs` 中找到；
- [ ] `positive` 和 `negative` 没有写反；
- [ ] 一采和二采没有映射到同一个错误节点；
- [ ] `base_model` 指向真正参与最终输出的加载节点；
- [ ] `filename_prefix` 指向最终 `SaveImage`；
- [ ] LoRA 节点接受 JSON 字符串协议；
- [ ] 自定义节点已安装且 ComfyUI 启动时无导入错误；
- [ ] 模型文件名和目录正确；
- [ ] 配置中没有个人路径、令牌、配对码或代理密码；
- [ ] 原 `config.json` 已备份；
- [ ] 希望保留的内置工作流仍在 `workflows` 数组中；
- [ ] ComfyUI 网页可以独立运行该模板；
- [ ] APP 修改的每项参数均通过实际生图验证；
- [ ] Gateway 和 APP 均能显示完成结果。

## 二十、项目维护者分发公共工作流时的附加要求

如果准备把工作流随 Canvas 安装器或发行资源公开分发，还应完成以下工作：

1. 删除工作流中的私人提示词、私人图片文件名和本机绝对路径；
2. 不分发无权再分发的模型、LoRA、图片或节点代码；
3. 为第三方节点保留项目名称、官方来源、许可证和版本；
4. 对 GPL 等再分发组件履行对应的源码和许可证义务；
5. 对所有压缩包生成 SHA-256；
6. 在干净 ComfyUI 环境中测试安装；
7. 检查模板是否会调用外部网络服务；
8. 检查工作流元数据和示例图片中是否存在隐私信息；
9. 对安装器中的可选第三方组件提供清晰、独立的授权说明；
10. 不要把第三方节点代码直接改名为 Canvas 自有组件。

对于 WeiLin LoRA 堆，更稳妥的分发方式是把它作为**独立、可选的第三方组件**处理，而不是无说明地合并到 Canvas 的 MIT 源码中。若未来加入安装器，应固定上游版本或提交哈希、保留 GPL-2.0 许可证和源码来源，并允许用户不安装该组件。
